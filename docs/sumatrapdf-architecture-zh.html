benfzc/sumatrapdf · C++ / Win32

SumatraPDF 架構導覽

一套輕量、多格式的文件閱讀器。原版是純 Win32 的 Windows 程式；另有 src/ng/ 這條新產品線，目標是 macOS、Linux 與瀏覽器 (WebAssembly)。

授權 GPLv3 / AGPLv3（部分 BSD） PDF 核心 MuPDF 1.28.5 src/*.cpp 約 158k 行 src/ng 約 126k 行 src/base 約 29k 行

專案概覽

SumatraPDF 支援 PDF、EPUB、MOBI、CBZ/CBR、FB2、CHM、XPS、DjVu 等格式，強調啟動快、檔案小、介面簡潔。程式以 C++ 撰寫，不使用 STL，字串、容器、檔案 I/O 等基礎設施都在 src/base/ 自行實作。

第三方函式庫放在 ext/。ext/mupdf 直接在原地修改，每個改動都要同時在 ext/patches/ 留一份 patch；ext/a-* 是由 cmd/amalgam.ts 產生的 amalgamation（把整個函式庫合併成少數幾個 .c 檔），不可手改。建置腳本是 TypeScript，用 bun 執行。

兩條產品線

原版 SumatraPDF（src/）

  • 只支援 Windows，直接使用 Win32 API
  • 繪圖：Direct2D / GDI+
  • HTML 類內容用 WebView2（Markdown、CHM）
  • 建置：bun cmd/build.ts → out/dbg64/SumatraPDF.exe
  • 舊的 macOS/Linux 移植與 MinGW/Wine 建置已移除

SumatraPDF ng（src/ng/）

  • 目標平台：macOS、Linux、WebAssembly；Windows 版只用於測試比對
  • UI 建立在 ext/gpui（gpui-kit-cpp 的 amalgamated 版本）
  • 平台相關程式以檔名後綴區分：_posix、_linux、_mac.mm、_wasm
  • 建置：bun cmd/ng-build.ts -linux|-mac|-wasm
  • 和原版共用 src/base、src/shared、ext/

開檔與繪製流程

以開啟一個 PDF 為例。對熟悉 Linux 的人來說，可以把 EngineBase 想成 driver 的 ops table，PageRenderService 像一個 worker thread 加上 page cache。

sequenceDiagram
    participant U as 使用者
    participant W as MainWindow / WindowTab
    participant C as EngineCreate
    participant E as EngineMupdf
    participant D as DisplayModel
    participant R as PageRenderService
    U->>W: 開啟 file.pdf
    W->>C: CreateEngineFromFile(path)
    C->>C: GuessFileType 判斷格式
    C->>E: CreateEngineMupdfFromFile()
    E-->>W: EngineBase*
    W->>D: 建立 DisplayModel(engine)
    D->>D: 依縮放與檢視模式計算頁面位置
    D->>R: RequestRendering(可見頁 + 預測頁)
    R->>E: RenderPage(args)（背景執行緒）
    E-->>R: Pixmap
    R-->>W: onPageReady → Repaint
    W-->>U: Canvas 顯示頁面

適合的平台

平台狀態說明
Windows 10 / 11，x64主要平台完整功能。預設建置目標；需要 Visual Studio 工具鏈。Markdown / CHM 依賴 WebView2
Windows，x86 (32-bit)支援僅 release：bun cmd/build.ts -rel -32
Linux 桌面（X11）ng 開發中需要 X11、cairo、pangocairo、gdk-pixbuf、glib、fontconfig、openssl；WebKitGTK 4.1 為選配。未見 Wayland 原生後端，需靠 XWayland
macOSng 開發中只能在 macOS 主機上建置，需 Xcode command line tools
瀏覽器（WebAssembly）ng 開發中用 emscripten 建置，任何主機都可編譯
Embedded Linux（無 X11 / framebuffer）不適合見下方說明

從 embedded Linux 角度看

ng 的 Linux 版是桌面程式：相依 X11 + cairo + pango + glib 整套 GTK 周邊函式庫，頁面快取預設上限 96 MB，加上 MuPDF、HarfBuzz、FreeType 及多種影像 codec，binary 與記憶體占用對小型板子偏重，也沒有 DRM/KMS 或 framebuffer 後端。

如果要在嵌入式裝置顯示 PDF，比較實際的做法是直接用 ext/mupdf（C API，可裁掉不需要的字型與 codec）把頁面畫成 pixmap，再自己寫到 /dev/fb0 或 DRM dumb buffer。SumatraPDF 的 EngineMupdf.cpp 是參考 MuPDF 用法的好範例。有 X11 且 RAM 充足（例如 512 MB 以上的 ARM 板）的話，ng 版可以嘗試，但目前不是官方目標。

建置與測試

# Windows original app
bun cmd/build.ts -dbg          # -> out/dbg64/SumatraPDF.exe
bun cmd/build.ts -rel          # release x64
bun cmd/build.ts -rel -32      # release x86
bun cmd/build.ts -asan         # AddressSanitizer build

# Unit tests (debug builds only)
bun cmd/run-unit-tests.ts -dbg

# Ad-hoc run without touching user settings
out/dbg64/SumatraPDF.exe -for-testing file.pdf

# ng: Linux / macOS / WebAssembly
sudo apt install build-essential pkg-config libx11-dev libcairo2-dev \
  libpango1.0-dev libgdk-pixbuf-2.0-dev libglib2.0-dev libssl-dev
bun cmd/ng-build.ts -linux -dbg
bun cmd/ng-build.ts -mac -dbg
bun cmd/ng-build.ts -wasm -rel

修改 src/ 的 C/C++ 後要跑 clang-format；修改 cmd/ 的 .ts 後跑 bun cmd/format.ts。vs2022/ 內有 Visual Studio 方案檔，可用 IDE 開發除錯。
